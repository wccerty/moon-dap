# 规则引擎调试示例

规则包是 JSON 对象，包含入口规则名 `entry`、JSON 输入数据 `input`，以及 `sources` 源码数组。每个源码对象包含 `name` 和 `text`。运行时在内存中编译和保存源码，调试客户端可通过 `loadedSources` 列出源码，通过 `source` 读取原文。断点可用返回的 `sourceReference` 配置。

[示例规则包](demo.json) 计算订单价格并打印审批分数。它包含 `main.rule` 和 `pricing.rule` 两份虚拟源码。

| 语法 | 含义 |
| --- | --- |
| `rule 名称 参数` 和 `end` | 定义函数及其单个参数，每个调用帧拥有自己的局部变量。 |
| `let 名称 = 表达式` | 计算表达式并绑定变量。 |
| `json 名称 = JSON` | 绑定 JSON 字面值，支持对象和数组。 |
| `call 结果 = 规则名 表达式` | 调用其他规则并绑定其返回值。 |
| `label 名称`、`goto 名称`、`when 名称 条件` | 定义跳转位置、无条件跳转、按布尔条件跳转。 |
| `emit 表达式`、`assert 表达式`、`return 表达式` | 输出、检查断言、返回值。 |

表达式支持变量、字符串、数值、布尔值、空值、括号、字段访问、数组下标、四则运算和短路逻辑。数字计算使用双精度浮点。源行和调试操作由规则 VM 推进。

## 构建与复现

在仓库根目录执行。

```text
moon build --target native
python -m pip install -r tests/requirements.txt
python scripts/test_rules.py
```

构建产物 `_build/native/debug/build/examples/rules/rules.exe` 使用 stdio。`launch` 接受 `bundle` JSON 对象，也接受 `program` 指向规则包文件。后者从文件读取 JSON，内部规则仍作为内存源码公开。

端到端脚本读取两份虚拟源码，使用函数断点进入 `price`，在暂停状态把订单数量从 2 改为 3，把嵌套审批分数从 4 改为 7。它随后检查条件和命中次数、日志断点、变量引用失效和异常栈，最后得到规则结果 22。用例也覆盖一次失败启动及同连接重试。

## 调试语义

- 命中次数支持 `N`、`==N`、`>=N` 和 `%N`。条件为真才计数，重新设置断点重置相应计数。
- 日志模板用 `{表达式}` 插值，用 `{{` 输出左花括号。符合条件的日志断点只发送输出事件。
- 赋值接受表达式及 JSON 对象或数组。替换容器会使该容器及其子容器的原引用失效，其他容器仍可访问。
- 补全支持当前帧变量及点号连接的对象字段。异常时保留规则调用栈，继续运行后以非零目标退出码结束。
- 本例的 `launch`、单线程及内存源码操作已由 stdio DAP 脚本验收。[完整测试](../../scripts/test_rules.py)
